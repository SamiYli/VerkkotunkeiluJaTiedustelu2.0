## a) Aja tunnilla esitetty ARP hyökkäys ja tutki, miten se toimii.
Olisin voinut käyttää host-konettani (windows) SSH-yhteyden muodostamiseen puTTY ohjelmalla, mutta minua epäilyttää ettei `xterm`-komennot avaa uusia terminaali-ikkunoita suoraan, koska windows käyttää eri ikkunointijärjestelmää (DWM) kuin linux (X11). Käytän siis Kali-virtuaalikonetta mininet-koneen komentamiseen, koska sillä on jo xterm.

### Otin SSH:lla yhteyden mininet koneeseen
```
ssh mininet@192.168.56.105
```
Mininet-koneen ip-osoitteen sain kirjautumalla ensin mininet-koneelle ja ajamalla siellä komennon `ifconfig`.

Mininetin käyttäjätunnus ja salasana on molemmat: `mininet`.

<img width="590" height="72" alt="image" src="https://github.com/user-attachments/assets/a87c460a-3855-4e59-8b55-63d6367c1f27" />

Sain kolme arvoa:
```
mininet-vm/unix:12  MIT-MAGIC-COOKIE-1  323c180daa9001596c851426e9390f91
mininet-vm/unix:11  MIT-MAGIC-COOKIE-1  912bc3e4fdbc2dc4610a8ee351c4a03e
mininet-vm/unix:10  MIT-MAGIC-COOKIE-1  7dc433b2ae54b62be422c8a8afdfcd2b
```
Nämä ovat varmaankin avoimia istuntoja, koska minulla on kaksi ssh-ikkunaa auki ja mininet-virtuaalikoneen komentorivi auki.

#### Seuraavaksi ohjeissa on edellisen arvon kopiointi seuraavaan komentoon:
```
sudo -s xauth add mininet-vm/unix:10 MIT-MAGIC-COOKIE-1 22ce67f9c6514c99d2903e2b9d97e496
```
Minulla on kolme arvoa, joten kokeilen ensin suurinta display numeroa 12. [Debian xauth man](https://manpages.debian.org/unstable/xauth/xauth.1.en.html)-sivun mukaan Saman koneen sisäisiin yhteyksiin viitataan muodossa: hostname/unix:displaynumber. Joten `mininet-vm/unix:12` on varmaan uusin ikkuna, koska sillä on suurin display numero.

Käytän siis komentoa:
```
sudo -s xauth add mininet-vm/unix:12  MIT-MAGIC-COOKIE-1  323c180daa9001596c851426e9390f91
```

<img width="724" height="33" alt="image" src="https://github.com/user-attachments/assets/79ad95f0-60a4-4084-bced-df30ca4fec2b" />

#### Kokeilin kaikilla MIT-MAGIC-COOKIE-1 arvoilla.

Xterm ei saa avattua terminaalia h1-nodelle.

Lueskelin mininet wikin [FAQ-sivuilta](https://github-wiki-see.page/m/mininet/mininet/wiki/FAQ) vinkkejä ongelmaan ja löysin sieltä kohdan jossa selitetään X11-forwarding ongelmista. Voi olla siis mahdollista, että minun olisi pitänyt käytää `-X` parametriä SSH komenossa, jotta olisin saanut X11 forwarding ominaisuudet käyttöön. Kokeilen siis avata uuden SSH-istunnon ja käytän siinä `-X` lippua.
